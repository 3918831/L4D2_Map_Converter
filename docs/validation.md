另以历史16号基线和17号真实捕获/日志回放当前反射导入流程，实际执行官方BSPZIP与VPK，生成BSP的SHA256为 `5541e7d1ef0f2c155c74379db698b061703cab8e54839bf19db78140383993d7`，与已验收18号逐字节相同，七文件包解包核对通过。这验证了导入链的结果保真，不是一次新的引擎采样或C6实机验收。

历史原始日志、完整地图和实验包保留在本机，源码发行只带精选结论，不附个人安装路径、账户标识或游戏文件。历史实机结论不能继承为新生成 VPK 的验收结论。

## 本版可重复检查

在源码根目录执行：

```powershell
python -m unittest discover -s tests -v
python -m l4d2_bsp.workflow --help
python -m l4d2_bsp.workflow check --config config.local.json
```

合成测试使用自建最小数据，覆盖容器/实体修改、受限风格、反射、路径、原生审计、打包和交接的正常及拒绝路径，不要求测试仓库携带官方 BSP。具体结果以本次测试输出为准，不能用测试数替代运行报告。

本机集成构建进一步调用真实 VRAD/VPK。它必须同时满足结构保护、模型光照审计、包解出文件一致和输入哈希保持。新流水线的 C2 集成证据应与历史 18 号实机证据分开记录；C6 用户测试不得通过复用 C2/历史捕获来冒充完成。

| 本次运行证据 | 位置或字段 | 回答的问题 |
|---|---|---|
| 配置、输入/工具哈希、状态 | `<run>/run.json` | 实际版本和配置、停在哪一步 |
| 原生编译日志 | `<run>/bake/vrad.log` | 缺模型、材质、警告或超时 |
| 保护结果 | `bake_audit`、`preflight` | 允许的风格变动、保护数据是否通过 |
| 天气策略 | `atmosphere_policy`、`preflight.base_style.weather`、各 `mode_styles` | replace/preserve、移除实体/分支、剩余雨实体、天气所有权与玩法保护 |
| 离线包验证 | `offline_package` | 包路径、SHA256、解包字节验证 |
| 本次人工命令 | `<run>/CAPTURE-STEPS.txt` | 当前 run 的实际控制台命令 |
| 原始捕获 | `<run>/evidence/attempt-XX/` | 本次采样 BSP 和引擎日志 |
| 导入过程 | `<run>/reflection-import/attempt-XX/` | 审计后回填及错误证据；失败不会覆盖旧 attempt |
| 最终结果 | `reflection_import`、`final_package` | 采样结构/资源检查及最终包身份 |
| 画面和玩法 | 用户保存的 PNG 与验收说明 | 实际挂载后的视觉与玩法是否可接受 |

本机清单和日志通常含绝对路径，分享前需脱敏。完整游戏资产不属于公开证据附件。

建议在本次运行目录另存 `USER-VALIDATION.md`，不要编辑工具清单来表达主观通过。可复制以下模板：

```markdown

- 已停用同图 addon、是否完整重启：
- HDR、分辨率、画质、FOV：

- 自选机位 ID、getpos 输出、PNG 文件：
- 天空/远雾、建筑/地面阴影：
- 车辆/武器反光、室内外曝光：
- replace：无原雨/风暴/闪电/雨声；preserve：原天气表现：
- 新娘 Witch 被惊动后的尸潮是否正常：
```

至少区分检查通过、离线构建通过、采样文件审计通过、画面接受和玩法路线检查。preserve 的动态天气可能在 guard 后变化；replace 也需要检查外部脚本和实际挂载后的行为。HDR 纹理格式审计不能判断反射是否符合期望氛围。三模式补丁静态处理不代表各模式完成实机测试。

## 已知风险与后续工作
