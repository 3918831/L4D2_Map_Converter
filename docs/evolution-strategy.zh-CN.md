# 通用化与 Agent 辅助演进策略

日期：2026-09-16。现状核对基线：本地 `main`，`b94dad0`（0.6.0）。

本文记录用户已认可的长期方向、基线源码中的限制，以及分阶段实施策略。2026-09-16 已获准开始通用部分，并要求每一步先回归已有功能。功能状态以各阶段证据为准；本文的长期目标不表示已全部实现。

后续统一称 C5M1 预设；已有 `c5m1-daylight-v1` 标识和预设内容保持不变。

## 1. 产品方向与验收原则

采用确定性的通用转换程序作为产品核心，Agent 作为未知情况分析与程序演进的辅助。正常转换不要求模型服务；完整游戏、地图资源及对应原生工具仍是运行依赖，最终场景 HDR 反射仍需游戏实际渲染。

程序按地图结构和能力处理输入，逐渐解除地图名称白名单。公开支持声明只覆盖有证据的输入、预设和实际测试范围。已测试地图清单是验收记录，不是未来的输入白名单。

未覆盖情况分为：尚未实现的通用规则、资源或格式能力不足、无法可靠判断的脚本语义、工具或运行环境异常。未知情况不等于不能程序化；也不能仅为通过构建而删除验证条件。

每次运行分别记录构建、结构审计、引擎采样、打包和人工验收状态。自动完成不等于人工验收通过；未执行的检查标记为未执行。部分转换须说明未覆盖项目，不能作为完整转换成功交付。

验收记录至少关联：输入 BSP 及实际使用的模式补丁哈希、预设 ID/版本/哈希、程序版本、原生工具版本或哈希、资源清单、游戏版本、运行模式、输出哈希、人工画面/路线结论及已知问题。已有 `run.json` 和资源快照可复用，但不能声称已完整记录整个游戏安装。

## 2. 已确认的转换范围

- 默认强预设覆盖：全局与局部雾、曝光、后处理、调色、天空、方向光，以及与目标天气冲突的氛围控制。室内外和局部分区默认覆盖，可选保留作为后续能力；不以保留作者氛围意图为默认目标。
- 默认保留局部灯光与材质；未来可以提供明确的可选修改策略。
- 可修改、删除或新增视觉实体及视觉 IO。原天气由区域或玩家触发，不要求继续保留该天气触发设计。
- 玩法推进、尸潮、机关、区域检测中的非天气功能继续保护。混合触发器应处理天气分支，不能因名称或天气关联而删除整个共享控制器。
- 新增天气体积和视觉几何属于用户允许的长期范围，但不纳入下一阶段必做项。现有 C4M3 预设继续表示固定阴天，不新增雨、雷电或暴风雨。
- 若未来新增降雨，预设可以选择不增加雨区或根据地图推导覆盖；动态天气可以采用预设随机控制，不必复刻原关卡触发。
- 主观画面由用户验收，自动参数与结构检查提供客观证据；无异常、无劣化是人工验收的重要部分。

## 3. 当前工程确实存在的地图专用限制

以下根据当前源码核对。目标参数已提取为预设，不代表来源地图已通用。

| 位置 | 当前限制 | 通用化方向 |
|---|---|---|
| `l4d2_bsp/configuration.py` | `MAPS` 只登记 C2/C6；限定来源与预设组合；强制 h/l/s 三份 LMP；按已知地图检查文件名 | 从实际输入发现地图身份及有效模式补丁；依据能力选择转换路径 |
| `l4d2_bsp/presets.py` | 默认来源集合为 C2/C6；schema 2 强制来源为 C2；部分角色仍含已知控制器名称 | 分离目标参数、来源识别与能力要求，消除目标预设对来源地图名的依赖 |
| `l4d2_bsp/source_atmosphere.py` | 检查 C2 的 world 范围、音乐标识和天空；固定雾/后处理/调色名称、数量及两个风控制器；环境音按 C2 名称映射 | 按实体类型、字段和控制关系识别角色，明确缺失、多实例和冲突策略 |
| `l4d2_bsp/style.py`、`profiles.py` | C2/C6 分支、已知实体布局和曝光控制器名称；C2→C5M1 保留历史 preserve 路径 | 保留旧行为供复现；新构建逐步迁移至共用转换路径 |
| `l4d2_bsp/weather.py` | C6 天气实体按 Hammer ID、类型、名称和控制签名匹配 | 按控制关系识别视觉分支；无法确认的共享控制或脚本明确报告 |
| `l4d2_bsp/reflections.py`、`auto_capture.py` | 采样依赖名为 `tonemap_global` 的控制器；反射格式只接收已验证布局 | 将采样目标绑定到本次角色识别结果；格式能力逐项扩展并验证 |

还有一些应当保留的严格检查：BSP/lump 布局、模型缓存拓扑、受保护数据、VTF 格式、资源身份和采样来源。这些不是地图专用参数。遇到合法但未支持的格式，应实现相应解析与验证，再扩大支持范围。

现有 BSP 读写、实体解析、VRAD 调度、光照审计、资源快照、反射导入、原生打包与自动采样流程具备复用价值。需要重点改造的是输入假设、角色定位和控制归属，不需要重写整个工程。

此前地图专用约束有助于固定实验边界和复现已接受结果，但不适合作为通用产品的长期入口。公开文档应持续明确“当前受限实现”和“未来通用目标”，不能把预设可扩展表述为输入地图已通用。

## 4. 通用核心与 Agent 的职责

建议共用流程：

```text
输入地图与资源 + 目标预设
           ↓
结构/资源/模式检查与角色识别
           ↓
结构化修改方案 + 能力报告 + 未解决项
           ↓
确定性执行 → 烘焙 → 审计 → 引擎采样 → 打包
           ↓
运行证据与人工验收记录
```

修改方案应记录输入身份、规则版本、每项改动的实体/字段或 IO 定位、原值与目标值、修改理由及适用前提。执行前检查方案与输入一致，执行后按保护约定检查。首先服务于现有 CLI，不提前引入模型服务或多套执行入口。

Agent 初期面向维护者：读取失败报告，调用检查工具，调查实体/资源/脚本，提出候选方案或代码修复。Skill 保存调查步骤、判断原则和证据要求；插件提供稳定工具接口。二者不能代替解析器、审计和测试。

Agent 不在普通批量转换中任意编写并执行一次性脚本。成熟判断应沉淀为通用规则和回归测试；尚未成熟的候选修改保留独立实验身份，不能直接计入稳定支持。

结构检查证明执行符合方案，不证明方案的玩法语义一定正确。复杂脚本、动态目标名、外部或加密脚本仍可能需要人工分析与运行验证。未来开放终端用户 Agent 模式，需另行验证其成功率、成本、失败恢复和可复现性。

## 5. 建议的近期推进顺序

### 阶段 A：建立通用输入与分析路径

1. 根据实际输入确定地图名称、BSP/模式补丁和资源关系，解除固定 h/l/s 集合假设。未提供、实际不存在和查找失败须区分；不伪造缺失补丁或生成缺失 NAV。
2. 产出实体角色、实例数量、视觉 IO 写入来源、天气关联、资源缺失及格式能力报告。处理实体不存在、同类多实体、名称不同等情况。
3. 明确哪些缺失角色可按预设创建，哪些需要空间信息或特殊结构；无法推导时给出原因。不能简单地“找到第一个实体就改”。
4. 建立结构化修改方案，保留现有执行和审计能力。

阶段 A 的完成标志是能够对 C2/C6 之外的地图产生有用的分析和方案，或给出具体能力缺口，而不是在地图名称检查处直接退出。

### 阶段 B：跑通通用强预设转换

1. 将 C5M1/C4 的目标值与来源名称解耦。旧预设文件及旧运行身份不原地改写；影响行为或语义的迁移使用明确的新版本。
2. 共用实体覆盖与视觉 IO 处理逻辑；按通用规则处理天气末端及已识别分支，保留混合事件中的非天气功能。
3. 采样控制器身份由本次方案提供，排除名称冲突，解除固定 `tonemap_global` 的输入假设。
4. 同步处理实际模式集合、地图专属资源、采样别名、最终原名与打包清单，避免入口已通用而后续阶段仍依赖固定地图布局。
5. 保留旧 C2/C6 配置的复现能力；新通用路径以参数、保护范围和实机结果做回归，不能把与旧结果字节不同一概视为错误。

C1M1→C5M1 和 C3M1→C4M3 已完成独立目录端到端转换，并获用户在实际观察范围内无异常反馈。随后以 C6M1 的复杂天气事件扩展通用规则，再纳入三方地图。

用户此前提出的独立交付验收继续有效：从将要发布的内容复制或克隆到独立目录，使用已打包原生工具，对非 C2/C6 地图完成转换和对应检查，并由用户验收。原生二进制如何随克隆交付需明确落实；仅在开发机的忽略目录中存在 ZIP 不满足该要求。

### 阶段 C：批量测试与维护者 Agent

建立批量任务清单、每图阶段状态、失败分类和人工验收入口。用官方及三方地图积累案例，避免一个失败中断整批；部署和游戏采样按共享安装资源串行协调。

演进闭环：失败样本 → 原因定位 → 可复用规则 → 回归测试 → 多地图复验 → 更新验证清单。必要的地图专用例外须显式标记，不能冒充通用规则。

在诊断产物和调用接口稳定后，整理维护者 Skill/插件。普通程序持续承担可靠执行，Agent 帮助缩短发现与修复新问题的过程。

## 6. 下一阶段的完成标准与暂缓项

- 新通用入口不依赖 C2/C6 地图白名单或某张地图的世界坐标、音乐标识、固定实体名及数量。
- C5M1/C4 目标预设不因输入地图名不同而直接拒绝；实际能力不足仍须给出具体报告。
- 至少完成一张非 C2/C6 地图的独立目录端到端验证；这证明通用路径新增覆盖，不证明任意地图兼容。
- 原有已接受路径与运行不被破坏；非天气玩法保护及格式检查不降低。
- 文档区分程序处理完成、结构检查通过、游戏采样完成与人工验收通过。
- 暂缓新增暴雨/雷电/雨区几何、GUI/独立 EXE、任意脚本语义解释及终端用户 Agent 产品化。

## 7. 逐阶段回归门槛

每一步完成后，先验证新增功能，再检查旧功能，通过后进入下一步。旧路径要求配置兼容、既有参数和保护规则不变；新统一覆盖路径允许明确记录的视觉差异，不要求新旧 BSP 全文件字节一致。

| 改动 | 必须检查 |
|---|---|
| 输入发现 | 任意合法地图名、实际补丁集合、目录优先级、缺失和歧义；旧配置测试 |
| 角色和 IO 分析 | 多实例/缺失角色、重复输出、混合天气与玩法、脚本及动态目标；完整回归 |
| 预设与修改执行 | 原值与目标值、修改清单、未修改实体/IO、保护数据、预设身份 |
| 烘焙与采样 | 相关原生工具验证、光照/模型/反射审计、失败恢复 |
| 独立交付 | 独立目录及打包工具、非 C2/C6 地图端到端转换、用户画面和游玩验收 |

不因只读输入分析改动重复要求用户进入游戏；影响实际输出时才增加相应原生或实机检查。自动检查通过、工具执行完成和人工验收分别记录。

## 8. 记录与实施范围

最初讨论轮仅新增策略文档与 README 索引。随后按用户确认开始阶段 A：通用只读分析，见 [第一阶段使用说明](generic-analysis.zh-CN.md)。该阶段不修改旧构建行为，不代表通用转换或新地图实机验收已完成。后续继续阶段 B 的通用修改与转换，不以增加单张地图白名单作为主要演进方式。

阶段 B 已接入独立通用入口和参数保护检查，使用方法、覆盖规则及当前验证范围见 [通用转换指南](generic-conversion.zh-CN.md)。旧来源适配继续保留，通用路径的测试结果单独记录。

## 9. 后续验证中发现的具体缺口（2026-09-16）

在保持阶段 B 转换代码不变的情况下，C2M1→C5M1 的通用入口通过基础图及 h/l/s 参数和保护预检查，尚未据此重新烘焙或人工验收。C6M1→C5M1 通用入口在 `relay_storm_blendin` 的 `SetEndDistLerpTo` 输入处明确拒绝；这是第一个阻断点，不表示只增加这一种输入就能完成 C6 天气覆盖。旧 C6 专用路径仍保留。

后续应按实体输入语义扩展雾渐变等规则，检查同一控制链的降水 alpha、模板风、雷声、闪电曝光、粒子及共享玩法分支，增加混合输出和生命周期保护回归，再做新通用 C6 的完整验证。不要直接把整个风暴 relay 或按名称匹配到的任意实体删掉，也不要因预检查通过就声称运行时天气覆盖完整。

### v2 扩展进展（2026-09-16）

`generic-replace-v2` 已完成上述雾渐变、降水 alpha、模板风、目录内天气声音/混音、纯画面震动与单一天空雾命令的通用规则和保护测试。C6M1 基础图及 h/l/s 通过检查，随后从独立源码目录使用八文件工具包完成烘焙和 48 份 HDR 自动采样。旧 v1 行为保留。2026-09-17 用户接受 C6 新结果的实际观察范围，保留白椅局部过亮 VIS-001；Phong 开关未改善，根因未确定、按用户要求暂缓。

未知粒子、脚本动态创建目标和未解析输出仍报告，不能以天气事件的可达性删除整个共享控制链。下一步为批量官方/三方测试建立每图阶段状态、失败分类及人工结果记录；暂不新增天气生成或终端用户 Agent 模式。

### 阶段 C 的实施顺序

1. 先固化任务清单与报告：每项绑定输入、目标预设、规则版本和独立运行目录；机器阶段与人工结论分开，允许“带已知限制接受”。
2. 增加只读批量预检查和汇总，缺资源、格式不支持、实体/IO 歧义分别记录；某图失败不阻断其他图。此步不改变转换算法，无需先批量启动游戏。
3. 再串行协调构建、引擎采样、恢复与部署；复用已有命令和收据，不绕过保护检查，不同时争用同一游戏安装。
4. 使用者逐图复核，保留截图和具体问题；已有 C1/C3/C6 结果作为回归证据，其他输入仍为未验证。新增通用规则先经小范围复验，再扩大批次。

白椅 VIS-001 与本机游戏操作问题暂不作为该阶段的前置修复；后者按用户要求等待再次出现。

2026-09-17 已实现前两项的首版 `batch-check`，见 [批量工作流指南](batch-testing.zh-CN.md)。它复用单图 check，保存配置、输入与程序身份，逐项隔离失败并记录检查点；机器阶段与人工状态分开。预检查通过不自动增加实机验证地图清单。

随后接入首版 `batch-run`，串行复用单图 build/auto-capture，核对预检查、构建及最终包身份。单图预期离线失败可继续；采样、清理、共享环境和内部异常停止队列。尚未实现自动重试/续跑、最终包部署和人工结论录入命令；先用 C7M1→C4M3、C4M3→C5M1 小批次验证实际转换，结果见 validation.md，不提前声明人工验收。
