# 架构与数据保护

转换以原始 BSP 为编译输入，在副本中改变受限视觉字段，再调用 L4D2 原生 VRAD 重算光照。流程不经过 VMF、VBSP 或 VVIS，因此不重新构建几何、碰撞或 PVS 数据；输出仍须通过逐项审计，不能仅凭这一路径宣称无损。

## 管线

```text
JSON 配置 + 原图 BSP/NAV/三模式 LMP + 版本化目标预设 + 本机资源/工具
  → check：身份、结构、风格字段和资源检查
  → build：配置/输入快照 → 视觉字段 → 官方 HDR VRAD → 保护审计
  → 官方 VPK 打包 + 解包逐字节验证 → offline_ready（旧反射）
  → prepare-capture → install-capture → 用户启动游戏/检查/采样/退出
  → collect-capture → finish-capture：来源与纹理审计 → 原名回填
  → 官方 VPK 打包 + 解包验证 → final_ready_pending_user_validation
  → remove-capture + 用户原名地图验收
```

用户截图只服务于验收。HDR cubemap 是游戏渲染的反射资源，进入最终 BSP 的数据来自原生捕获文件。

## 模块与边界

| 模块 | 职责 |
|---|---|
| `binary.py`、`entities.py`、`inspect.py` | L4D2 v21 容器、实体解析、结构与 I/O 审计 |
| `patch.py` | 原有白名单等长定点修改；不承担全局风格转换 |
| `presets.py`、`preset_data/` | 校验并加载固定版本的目标参数、资源引用、曝光和天气策略；提供角色视图与 SHA256 身份，不读取 donor BSP |
| `style.py`、`profiles.py` | 明确的来源/目标兼容组合：C2/C6→C5 与C2→C4；唯一实体/字段、已知值、玩法输出保护和重复应用检查 |
| `weather.py` | 受限 C6 天气所有权签名、混合事件分支移除、局部后处理/雨声覆盖；不改几何数据 |
| `soundscapes.py` | 从预设的受限声音定义生成地图专属脚本及资源依赖；原名包与临时采样别名分别生成，不修改全局声音脚本 |
| `configuration.py` | JSON 配置、路径、来源适配器与目标预设选择、源图身份、输入与工具哈希；兼容显式参考文件旧配置 |

| `native_mounts.py` | 可选生成编译目录内的绝对资源挂载配置，解决独立工具的 DLC 搜索路径问题；真实游戏配置保持不变 |
| `model_lighting.py` | 对应静态模型的资源快照、MDL/VVD/VTX 光照布局核验与有证据的旧 VHV 缓存迁移 |
| `reflections.py` | 纯字节采样交接、guard 控制文件、HDR 来源/格式审计 |
| `handoff.py` | 用户主动调用的临时安装、收据、游戏退出检查、归档及精确清理 |
| `workflow.py` | 阶段编排、`run.json`、失败信息和产物追踪 |

## 保护合同

使用 `native_mounts: resource_roots` 时，VRAD 根据明确的完整资源重新烘焙；允许其修改 v1 叶节点的两个天空可见标记位，并独立报告变更数量。叶节点所有其他字段、区域/碰撞、原始 PVS 数据仍受保护。旧 `gameinfo` 模式继续要求叶数据完全一致。字段来源和本轮 C6 对照见 [独立工具包验证](native-tools.zh-CN.md)。

风格阶段仅支持已知地图和实体形状；未知、重复或歧义目标会拒绝处理。基础 BSP 与三份模式实体 LMP 一起迁移，避免有效模式补丁重新覆盖风格。NAV 及可选 exclude 文件保持原字节。C2→C5 使用已有受限 `preserve` 配置；C6→C5 默认 `replace` 接管原天气和局部氛围，显式 `preserve` 则使用旧版保留风暴行为。C2→C4 只接受 `replace`，C6→C4 尚未开放。

C4 schema 2 把可选太阳、缺省曝光项、普通风和完整氛围角色与 C5 schema 1 分开表达。C2 适配器覆盖各雾区、后处理、主/开场/检查点调色入口和环境音，保留开场相机、控制器切换时序及无关 I/O；未知氛围写入者拒绝处理。天空几何、局部灯光/材质、事件音与玩法结构保留。固定目标采用 C4 初始化默认参数，曝光 max 10、基础雾 end 1500，不含太阳光斑、新增雨、雷电或动态风暴，也不导入 C4 Director 脚本。

C4 声音只包含经筛选的非天气室内 room-tone；室外移除天气后有意不加循环声。工作流生成并审计 `scripts/soundscapes_c2m1_highway.txt`，采样时另生成对应别名脚本，最终包恢复原名脚本。提供 exclude 时，原名包为 BSP、三模式 LMP、NAV、exclude、addon 描述和 soundscape 共八文件；C5 原七文件布局保持不变。

C6 replace 先把三个雾控制器的完整现有目标字段统一为 C5 master，再按 34 个已知天气实体的 Hammer ID、类别、名称和控制字段 SHA256 验证所有权。控制签名包含 On/Out 输出、ESC 值、模板与脚本字段，能防止天气实体内新增的玩法输出被一并删除。移除的是活动实体文本；原有雨区模型等非实体 BSP 数据保持，既不重新构建刷体，也不删除其底层索引。

天气链以外只有明确核实的新娘 Witch 风暴分支可移除，其尸潮输出及其他字段保留。未知输入天气链的事件、模板引用和非许可氛围写入者会拒绝。三个后处理控制器采用 C5 exterior，检查点调色改为 C5 main；原雾区路由只作为等效目标效果的载体保留。56 个环境音区域改为 C5 水岸/商店的无雨定义，区域位置和半径不变。剩余实体逐项比对预期字段，未触及实体逐字节核对，所有保留输出（含 OutAnger 类）核对顺序和值。允许的天气/视觉修改有明确审计，不能概括为全部 I/O 均不变。

这不是任意脚本的语义分析器。原关卡 BeginScript 调用和加密 .nuc 保留；没有证明外部脚本、addon 或特殊运行模式绝不重新改变天气。因此 replace 的静态结果和完整路线实机结论分别报告。增加其他地图需要新的来源适配；0.3.0 已分离目标预设参数，新增天气体积尚未实现。

来源适配器负责地图身份、实体角色定位、天气所有权和玩法保护；目标预设负责这些角色应获得的参数及资源引用；工作流负责烘焙、快照、采样与打包。`StylePreset` 通过校验后的角色视图接入原转换接口，不伪造 donor BSP，也不把 C5 的位置、几何或玩法事件移植到来源图。旧接口仍接收显式参考字节。接口与扩展要求见 [预设说明](presets.md)。

VRAD 后，实体块与非许可 lump 内容必须保持。光照相关 lump 也有内部约束：HDR face 只能改变已知光照字段，静态模型 `sprp` payload 不变，detail prop 保留字典和布置，PAK 只允许识别出的原生 HDR 静态模型光照流变化。VHV 的拓扑、校验和、记录范围与填充接受结构检查。容器偏移可以随重写改变，不以整文件字节相同作为烘焙验收条件。

0.1.1 增加历史模型光照缓存迁移：默认无模型证据时，VHV 非颜色字段仍要求完全一致。工作流在烘焙前按原 `sprp v9` 模型索引读取当前资源；若模型 checksum 与旧 VHV 不同，以对应 MDL v49/VVD v4/DX90 VTX v7 的一致校验值、合法顶点索引和有序 `(LOD, 顶点数)` strip group 核对新 VHV。只接受这些明确验证的缓存布局变化，保持 `sprp` 和其他保护不变；不会导入或修改模型文件。解析器只验证光照布局需要的结构，不声称全面验证任意模型格式。

模型资源通过 VPK preload/payload 的范围与 CRC 校验，或读取 loose file/BSP 内嵌内容，记录 SHA256 和来源。构建前建立快照，烘焙后、打包后和后续运行加载时重新核对；更高查询优先级出现新资源也会使快照失效。MDL 校验值已匹配旧缓存的模型也记录 VVD/VTX 伴随资源。查询顺序是配置约定，同目录候选有歧义则拒绝，游戏实际挂载与 addon 覆盖仍需实机确认。

反射导入检查本次基线和唯一别名、未改动的非 PAK 数据、原有 PAK 资源、采样坐标集合、支持的 HDR VTF 布局和有限 RGB 值，并记录各采样纹理是否发生字节变化；同字节数量会单列，不能仅凭纹理变化与否认定画面改善。当前只接收已经观察到的有限 VTF 变体；不支持的格式拒绝导入。原生捕获的 alpha 特性不能当作颜色质量证明。只回填采样 HDR 反射，原 LDR 与默认反射保留。

生成的采样加载命令设置 LAN=1，VScript 同时检查实际 HDR、镜面、曝光、正确别名和已连接的本地主机。进程启动参数 `-insecure` 与 `status` 的 VAC 状态由用户核对，LAN/cheats 不替代它。原生 buildcubemaps 重载会重置会话 guard；不得重复请求。日志审计要求同一 run/别名的有序 guard 与唯一请求，保留请求后的拒绝作为诊断，不以重新进图成功作为反射写入判据。

BSPZIP 完成后再次核对除 PAK 外的内容及逐资源替换集合；VPK 完成后用官方工具解包，核对每个预期文件的字节。工具退出 0、`CAPTURE_REQUESTED` 或完成提示，都不能替代这些检查。

## 运行与恢复

`run.json` 记录本机配置、输入清单、哈希、原生命令、阶段状态、审计和产物。后续操作检查输入及追踪产物是否变化；配置文件本身也属于输入。记录覆盖明确输入、工具及部分运行依赖，不是整个游戏资源安装的完整不可变快照。运行期间应保持安装资源不变，挂载优先级仍需实机确认。

预设运行另外记录预设 ID、版本及 JSON 内容 SHA256，并追踪所用预设文件。已有 donor 运行按原清单继续核验，不补写预设身份，不修改原配置。参数更新应发布新预设版本并创建新运行；同名预设不能在运行过程中悄悄换值。

输出目录与游戏/工具安装分离，构建拒绝已存在的输出目录。失败阶段保留日志与产物；本版没有自动续跑烘焙或通用缓存恢复。采样可归档多次 evidence attempt，导入/打包失败也可在编号 attempt 中重试，但捕获必须来自本次基线和别名。

显式 `install-capture`/`remove-capture` 或 `auto-capture` 操作临时安装。清理根据安装收据校验精确目标，不要求旧输入仍存在。发布 VPK 由用户退出游戏后手动部署。临时别名解决采样隔离问题，不能代替原名地图的玩法验收。

### 可选自动采样

`launch.py` 负责严格启动配置、正常启动器、实际游戏进程路径与启动参数核验、INI 比较恢复及进程识别。`auto_capture.py` 负责一次性运行日志、同运行/同游戏安装互斥、临时 CFG/VScript、磁盘命令、超时、归档与清理；`workflow.py` 仅增加命令入口。转换配置和旧运行清单保持兼容。

直接在 `map` 后紧接 `script_execute` 会早于本地游戏就绪。自动路径使用 `lservercfgfile` 指定本轮 ready CFG，先执行用户配置的正常 listen-server CFG，再启动原生 `AddThinkToEnt` 控制器。它检查主机、队伍/生命、开场镜头与冻结标志，连续等待后关闭镜面反射，再等待 HDR/曝光状态稳定。原有采样守卫仍核验精确地图别名、LAN、本地主机及目标曝光。

外部控制器通过 `ems` 文件发送一次 CAPTURE。VScript 在请求采样前记录 DISPATCHED，原生重载读取该状态后只进入 RELOADED。外部流程要求日志顺序和完整 BSP 审计通过，再请求 FINISH 与正常退出；退出后使用原 `collect`/`finish` 路径重新审计、回填原名并打包。没有 DLL 注入、进程内存修改或 UI 输入。原生等待是经验验证的保守状态观察，不是通用 GPU/曝光完成证明。

异常只能进入 STOP 恢复，不能在旧别名上再采样。启动器备份、请求日志和待清理收据保存在 `auto-capture` 目录；大文件归档通过可恢复的临时文件发布，避免中断留下截断的最终证据。清理前确认游戏关闭，且所有文件符合收据或本轮已归档输出。安装目录保留一个一字节 `.lmc-auto-capture.lock` 文件，内核锁在进程退出时释放，用于串行化共享启动器操作。配置中的 `listenserver_cfg` 是使用者声明的平时有效值，自动流程先执行它并在退出时恢复该设置。

## 原理依据

Valve 公开 VRAD 源码直接读取 BSP，计算光照并写回产物，支持“无需恢复 VMF 即可研究重烘焙”的架构依据；具体兼容性由本项目对 L4D2 官方工具和实图的审计确定。[Valve VRAD](https://github.com/ValveSoftware/source-sdk-2013/blob/b8cfb12c0e083a2ef5b2f9f9b50f3902fa034474/src/utils/vrad/vrad.cpp)

Valve 的默认 cubemap 实现将默认纹理与在引擎内生成场景反射区分。因此离线 VRAD 输出不能自动宣称已有新场景反射。[Valve cubemap 实现](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/utils/vbsp/cubemap.cpp)

Source SDK 2013 不是 L4D2 引擎源码或其原生工具替代品。公开源码用于说明结构，L4D2 的格式和行为以本机原生工具产物和实际游戏测试为依据。[Valve SDK 仓库](https://github.com/ValveSoftware/source-sdk-2013)

## 尚未覆盖

任意地图自动角色识别、自定义地图、任意用户预设导入、新增天气体积、无引擎等效反射渲染、全部材质依赖验证、GUI/EXE 和 S0—S7 阶段演示均未实现。自动采样仅覆盖已适配来源的 replace 路径与受支持的启动条件。内置预设不使 C7 或其他来源地图自动兼容。静态保护证据不包含完整游戏流程、所有画质/模式或联机兼容验收；用户对已有 C6 包的接受也不补足未记录的模式和路线覆盖。
